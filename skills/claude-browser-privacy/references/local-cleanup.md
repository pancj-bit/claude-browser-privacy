## Claude Code and Desktop

- **CLI login.** For each known configuration, including a user-specified `CLAUDE_CONFIG_DIR`, use `claude auth logout` or the installed CLI's `/logout`. Check `claude auth status` locally and report only sign-in state and auth method. On macOS also check for the corresponding Keychain item by service name only. All desktop platforms can have a `.credentials.json` in the config directory. Verify presence without displaying contents. If another method remains active, identify its source by name, such as `ANTHROPIC_API_KEY`, an OAuth token variable, or `apiKeyHelper`. Remove only the approved Claude-specific local entry from its actual source. Shared provider credentials and server-side keys have a wider scope. [Claude credential storage](https://code.claude.com/docs/en/authentication#credential-management) · [CLI commands](https://code.claude.com/docs/en/cli-reference)
- **Desktop login and app storage.** Use the app's sign-out control. Verify a signed-out screen and quit. Inspect the installed app's actual per-user data, cache and logs. Common locations include `~/Library/Application Support/Claude` on macOS, app-specific Roaming or packaged application data on Windows, and the app's XDG directories on Linux. For scoped cleanup select cache, logs, and session stores under confirmed app-owned paths. Pasted user content can live in a directory named `paste-cache`. A full Desktop reset can include local-only work and connector configurations. Show these before including them.
- **macOS helper.** If the sibling `claude-cleanup` skill is installed, read its instructions and run `python3 scripts/claude_cleanup.py --audit` from its directory. For approved cleanup it offers cache/log removal, the named CLI credential and optional Desktop reset. Use its interactive confirmation and report its backup and Trash locations. Leave identity rotation, app removal, and the helper's fixed Taipei option deselected. Its backup flow requires `~/.claude`. If that directory or the helper is absent, use native sign-out and move only confirmed app-owned items to Trash. Avoid running mutations from an active Claude Code process whose files are being cleared.
- **Full local removal.** Include Claude-owned history, settings, skills, backups, and Desktop local work in the inventory when the user asks for *all* data. Explain what would be lost, including session history under `~/.claude/projects`. Once the user approves those items, use the OS Trash or Recycle Bin for the specific Claude-owned paths. Inspect an overridden config path before treating its contents as disposable. Handle actual project folders, shared configuration, and other users' data only when specifically identified and authorized. Identify residual backups and Trash copies. Permanent removal needs consent for those exact items. [Claude Code data locations](https://code.claude.com/docs/en/setup#remove-configuration-files)

## Previously used browsers

Work in each existing profile that used Claude, including private-browser products with retained sessions if present. Use native site-data controls. Match exact domains or genuine subdomains of `claude.ai`, `claude.com`, and `anthropic.com` that the user used. Inspect the actual host before selecting it. Third-party identity providers may serve many unrelated sites.

| Browser | Site data controls |
| --- | --- |
| Chrome and Chromium derivatives | In Chrome open `chrome://settings/content/all` and delete the matching displayed entries. In Edge use Settings and search for **See all cookies and site data**. [Chrome instructions](https://support.google.com/chrome/answer/95647?hl=en) |
| Safari | Settings → Privacy → Manage Website Data. Select the matching sites and choose **Remove**. [Safari instructions](https://support.apple.com/guide/safari/manage-cookies-sfri11471/mac) |
| Firefox | Settings → Privacy & Security → Cookies and Site Data → Manage Data. Remove the matching entries and save changes. [Firefox instructions](https://support.mozilla.org/en-US/kb/clear-cookies-and-site-data-firefox) |

Check the profile's password manager for matching site entries and passkeys. Remove approved local entries without viewing or exporting secrets. Account-backed or synced deletion can propagate to other devices. Get authorization for that consequence or record the entry as retained. Keep unrelated Google, Apple and SSO credentials. Apply the same scope to matching browsing-history entries. [Chrome password storage](https://support.google.com/chrome/answer/95606?hl=en)
